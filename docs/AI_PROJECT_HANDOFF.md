## Proposed 3.9.2 — Motion/VFX activation and notification lifetime (branch fix/motion-notifications-392)
- **Owner feedback:** Real Windows screenshot from 3.9.1 Profile showed the app's motion switch ON but the diagnostic explicitly stated Windows reduced-motion was ON; pressing "Проверить движение" did not animate. This is a confirmed architectural mismatch: `motion.js` and `motion.css` enforced OS reduction even after an explicit app ON selection.
- **Persistence architecture:** The Electron backend binds a random localhost port each launch; browser localStorage is scoped to that port, so an ON toggle could be lost on restart. New `desktop/motion-preferences.cjs` stores the allowlisted `system|on|off` mode in Electron userData. Preload exposes only `emsMotion.get/set` through strictly main-frame, active-port-validated IPC. Old localStorage is migrated when accessible; no changes to auth, user DB, Ed25519 or update protocol.
- **Activation policy:** A previously stored `ems-motion-enabled=true` or newly toggled ON state counts as an explicit in-app opt-in, setting `html[data-motion=force]` and allowing visible motion even when Windows requests reduced motion. Without explicit opt-in, the OS preference remains authoritative; OFF still disables all decorative effects.
