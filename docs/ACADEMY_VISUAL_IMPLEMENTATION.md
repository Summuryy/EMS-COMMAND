# EMS COMMAND — визуальная Академия (план интеграции скриншотов)
Дата: 2026-11-12. Основано на присланных владельцем материалах больницы «Россия Онлайн», Кутузовский.

## Фактическое состояние
- В `main` приложения v3.10.0 есть 12 текстовых курсов `public/js/views/field-training.js`, рендеринг внутри `academy.js`, чек-листы с локальным хранением и тесты.
- 79 оригинальных PNG в отдельных архивах библиотеки ChatGPT (`/EMS COMMAND/`); они **не доставлены в исходный GitHub и не включены в Windows ZIP**.
- Создан локальный интерактивный прототип `EMS_COMMAND_ACADEMY_VISUAL_PREVIEW.zip` с WebP-версией 79 исходных файлов, 12 пошаговыми маршрутами и 46 тематическими размещениями иллюстраций. Он хранится отдельно в /EMS COMMAND/, **не считается установленным приложением**.
- Блокированный пункт: безопасная передача бинарных изображений в репозиторий и Windows CI, плюс проверка публикационной пригодности каждого кадра. Текущий текстовый GitHub-коннектор не копирует локальные файлы.

## Требования к крупному обновлению
1. Сохранить текущую ванильную JS/Electron архитектуру и раздел «Устав»; расширять `field-training.js` и CSS, не переписывать проект.
2. Обучение новичка: «Получить удостоверение» → собеседование → приглашение в Discord → инструктаж → тест → отчёт 1→2 → лекарства/ПМП → отчёт 2→3.
3. Для ОМП отдельно: запрет самостоятельных действий до завершения стажировки, собеседование (204/205), инструктаж 5+ минут с двумя скриншотами, проверка отчётов ⏱️→❌/✅ и К.А., нормативы 5→9, госволна.
4. Для ОПП отдельно: конкретные пороги 3→9, 80% ПМП вне больницы, смены/вакцины/таблетки/квалификации.
5. В каждом уроке: пользовательская задача → игровые действия → 1–3 релевантных изображения с понятной подписью → критерий успешного доказательства → типичные ошибки → пошаговый чек-лист.
6. Навигация «по роли» + поиск. Сохранение прогресса по отдельному пользователю без уничтожения данных после обновлений; offline и keyboard navigation.
7. Доказательства только с полным кадром, красной боди-камерой, плашкой, зоной и датой после последнего повышения. Решение принимает старший состав.
8. Следовать действующим правилам Discord; ссылки на разные тесты не считать равнозначными, исторические сроки не считать постоянными.
9. RP-лекарства и хирургия — не советы по реальной медицине.
10. Согласовать публичную безопасность иллюстраций: вырезать/размыть чужие Discord-имена, игровые идентификаторы/профили, уведомления и чаты, где они не нужны для учебной задачи. Не публиковать исходный ZIP в публичном GitHub или публичных релизах. До одобрения — только локальный прототип.

Файлы ссылок на изображения перечислены в `docs/ACADEMY_SCREENSHOT_INDEX.json`. Все пути `image(YYYYMMDD-HHMMSS).webp` являются **локальными ожидаемыми названиями**, а не утверждением, что файл присутствует в `public/assets`. Для production следует сохранять только очищенные утверждённые снимки с устойчивыми именами.

## Порядок внедрения
1. Забрать из библиотеки оригинальный/оптимизированный пакет и локальный учебный прототип; сопоставить изображения с уроками, вручную проверить отображаемые данные.
2. Создать версионированный `public/assets/training/` из **разрешённых к публикации** изображений (не выкладывать скриншоты людей/личных данных без необходимости).
3. Подключить проверенный каталог иллюстраций к `field-training.js`; учесть отсутствующие файлы и ошибки загрузки, lazy loading, lightbox, alt-тексты.
4. Добавить тесты наличия ассетов, сопоставления индекса изображений, CSP, escaping и локальной навигации; проверить 1280×720 и 1920×1080, reduced-motion и offline.
5. Выполнить npm run check, npm test, Windows smoke QA, Portable Launcher QA.
6. Создать подписанный **preview** релиз в `EMS-COMMAND-RELEASES`, проверить GitHub Actions, Ed25519, SHA256, manifest, ZIP и реальный канал `latest`; убедиться, что существующий лаунчер обнаруживает обновление.
7. Не объявлять официальный запуск без отдельного согласия владельца.
