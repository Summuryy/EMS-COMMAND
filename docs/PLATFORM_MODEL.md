# EMS COMMAND — multiple GTA 5 RP servers (requirements discovery)

Status: product discovery; do not treat examples as approved server rules. First supported environment: Россия Онлайн. Other servers (including Majestic RP) follow the same core model only after verifying requirements.

## Stable core across communities
- Personal account, server and in-game identity (a user's Static ID is scoped to their own server).
- Duty start/end and optional checklists; record actual events, never fabricate completed duties.
- Screenshot evidence archive with immutable source, server-specific labels, manual review when uncertain.
- Career progress over administrator-defined, versioned requirements. A progress meter must not imply automatic approval or rank change.
- Reference handbook with visible server and rule version; admins control content.
- Notifications, security, privacy, and export of a user's own evidence.

## Russia Online first
Use the owner's real rank table, faction handbook, promotion report formats and examples to configure it. Do not hardcode informal assumptions like treatment locations or universal counts. The names of departments, rank limits, time rules, bodycam rules, proofs and submission channels must be confirmed against the actual server guidelines.

## Future server adapters
Plan a versioned `server_profile` (platform / server ID / name / role schema / evidence categories / duty policy / promotion goals / report template / handbook source). Do not auto-migrate accounts across servers. Keep role authorization and evidence decisions server-scoped. Manual selection is the default; do not claim game API integrations that do not exist.

## Questions for the owner (no credentials or private screenshots needed)
1. Russia Online: exact hospital department structure, rank names, prerequisites, current promotion matrix, server name and revision date.
2. Representative promotion reports and annotated screenshots with personal data removed: which evidence qualifies, how many, how bodycam is confirmed.
3. New-player top three tasks and preferred onboarding order, including whether shifts or evidence may be recorded without an admin invitation.
4. A second server's official rules (Majestic or another) for comparison: roles, categories, duty timings and report destination.
5. Data policy: single-player local vs shared staff accounts, who approves evidence, how long screenshots are kept, and whether an offline mode is required.

## Validation
Do task-based UX testing with first-time and experienced users. Do not claim smooth Windows motion without end-user observation and startup/CPU/GPU evidence. Do not modify signing or launcher trust to deliver a UX update.
